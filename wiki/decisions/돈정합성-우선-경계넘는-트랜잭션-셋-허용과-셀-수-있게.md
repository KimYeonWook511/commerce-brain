# 돈 정합성이 aggregate 원칙을 이긴다 — 경계 넘는 트랜잭션 셋을 허용하고, 대신 셀 수 있게 만든다

## 갈라 쓰는 말 둘

```
aggregate 경계   한 번에 로드·저장하는 객체 덩어리의 경계.  결제 / 환불 / 주문 / 재고가 각각이다
도메인 경계      업무 영역의 경계.  결제와 환불은 같은 도메인 안, 주문·재고는 밖이다
```

## 컨텍스트 — 원칙대로 나누면 돈이 어긋난다

```
주문은 취소됐는데 환불 의도가 아직 없다   ←  그 사이에 죽으면 돈이 안 돌아간다
결제는 종결됐는데 되돌릴 환불이 없다      ←  나간 돈을 되돌릴 근거가 아무 데도 없다
```

**돈이 걸린 자리에 그 틈을 만드는 위험이 원칙을 지키는 이득보다 크다**고 보고 셋을 한 트랜잭션으로 묶었다. 이 판단 자체는 새로운 것이 아니다 — 단일 DB 조건에서 이벤트·Outbox 없이 트랜잭션 하나로 cross-aggregate 정합을 확보한다는 방향은 [[payment-order-트랜잭션-경계-cross-aggregate-단일tx]]·[[paid-order-취소환불-단일tx-의도와-standalone-cancel-대사]]가 이미 세웠다. 이번에 더한 것은 **그 예외를 세는 장치**다.

```
승인 확정        주문 + 결제              ★ 도메인 경계도 넘는다
승인 반려        결제 + 환불                 aggregate 둘이지만 같은 도메인 안이다
결제된 주문 취소  주문 + 결제 + 환불 + 재고   ★ 도메인 경계도 넘는다
```

## 결정 — 도메인 경계까지 넘는 것만 별도 클래스로 갈라 파일 단위로 센다

**그냥 허용한 것이 아니라 세는 장치를 함께 뒀다.** 도메인 경계까지 넘는 것만 별도 클래스로 갈라 **밖에 닿는 자리를 파일 단위로 셀 수 있게** 했다. 승인 반려는 결제 도메인 안에서 끝나므로 그 클래스로 가지 않는다.

> 같은 클래스에 두면 "여기 이미 주문을 만지네" 하고 둘째가 들어온다.

**"결제된 주문 취소"가 넷을 묶는 것에는 판단이 하나 더 붙는다** — 재고 복구가 그 최소 집합에 드는지는 따로 대 봐야 했고, 맨 뒤에 두는 것과 그 락 경합을 계측하는 갈래는 [[재고복구-트랜잭션-맨뒤-배치와-비관락-경합-계측갈래]].

## 트레이드오프

- 예외가 셋이라는 사실이 코드에 드러나지만, **늘어나는 것을 막는 장치는 없다.** 파일이 늘어나면 알아챌 수 있다는 것뿐이다.
- **더 나은 모양을 알면서 안 했다.** 불려 가는 쪽이 트랜잭션을 안 여는 협력 지점을 제공하면 "부르는 쪽이 경계를 연다"가 코드에 드러난다. 재고·결제 도메인을 함께 손대는 일이라 범위 밖으로 남겼다. **지금 모양이 틀린 것도 아니다.**

## 배운 것

- **원칙과 돈 정합성이 부딪히면 돈이 이긴다. 대신 어긴 자리를 셀 수 있게 만든다.** 예외를 허용하되 그 예외가 파일·클래스 단위로 드러나면 늘어나는 것을 알아챌 수 있다.
