# 간편결제 직접 연동 vs 결제대행사 — 하이브리드 전략 검토

현재는 네이버페이를 결제대행사 없이 직접 연동해 쓰고 있다. 그 선택을 유지할지, 결제대행사로 옮길지, 섞을지를 따져본 기록이며 **결론을 내리지 않았다.**

## 저울질한 것

**결제대행사 연동 vs 직접 연동의 경제성.** 소규모에선 결제대행사를 빼도 카드사·간편결제 수수료가 대부분 남아 절감이 거의 없고, 카드사 직접 계약은 규제·인프라상 사실상 불가능하다. 즉 **결제대행사 통합이 정답이다.** 개별 간편결제 직접 연동은 학습 가치는 있으나 결제수단마다 유지보수가 배가된다.

**하이브리드 전략(간편결제 직접 + 카드는 결제대행사).** 기술적으로 성립한다 — 결제대행사 위젯은 노출할 결제수단을 가맹점이 켜고 끌 수 있어 카드만 위젯으로 두고 간편결제를 뺄 수 있고, 간편결제 3종은 각자 직접 연동한다. 그러나 **"직접 연동하면 수수료가 싸다"는 조건부다.**

- 간편결제사 자체 수수료는 직접이든 결제대행사 경유든 어차피 내고, 직접으로 아끼는 건 **결제대행사 중개 마진뿐**이다.
- **소규모는 협상력이 없어 표준(높은) 요율을 받는 반면 결제대행사는 다수 가맹점을 묶어 더 낮은 통합 요율을 협상한다** — 소규모에선 직접 연동이 오히려 비쌀 수 있다.
- 카드는 직접 계약이 불가능해 결제대행사 경유가 사실상 유일하다.
- 운영상으로도 결제수단이 여러 갈래로 갈려 **승인·취소·부분환불·대사·정산을 각각 관리해야 한다.** 소규모에선 절감보다 복잡도 비용이 크다.

## 지금 상태

**절감은 거래 규모가 충분히 커야 유의미하다.** 지금 직접 연동을 유지하는 근거로 수수료를 대면 근거가 약하다.

> 학습 목적이라면 **"여러 연동 방식을 다뤄본다"가 수수료보다 정직한 근거다.**

실제로 직접 연동을 유지하는 대가가 이후 작업에서 계속 드러났다 — 결제사 명세가 말하지 않는 것을 실측으로 메워야 했고([[네이버페이-환불-api-실측-기록]]), 결과 불명 회수·이력 판정 근거를 우리가 직접 설계해야 했다([[결과회수-상한-폐지와-백오프-표-통지-반복]]). 결제사 하나에 맞춘 부분을 일반화하지 않고 남긴 자리도 있다([[결제사-연동타입-인프라-격리와-나가는-호출-읽기제한시간]]).

## 열린 질문

- 결정하려면 실제 거래 규모와 두 요율을 비교해야 하는데, 그 숫자가 없다.
- 두 번째 결제사를 붙이는 시점이 이 판단의 자연스러운 트리거다. 그때 "결제대행사 하나를 붙이는 것"과 "간편결제 하나를 더 직접 붙이는 것"의 비용을 비교하면 답이 나온다.
