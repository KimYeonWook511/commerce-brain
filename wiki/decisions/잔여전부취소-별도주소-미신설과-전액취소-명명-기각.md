# 잔여 전부 취소를 별도 주소로 두지 않고, "전액취소"라 부르지 않는다

## 결정 — 품목 목록을 생략하면 "그때 남아 있는 수량 전부"

취소 요청의 품목 목록을 생략하거나 비워 보내면 잔여 전부를 취소한다. **별도 주소를 신설하지 않는다** — 그것도 결국 부분취소의 특수한 경우라, 경로를 나누면 잔여수량 검증·재고 복구·상태 전이·중복 처리가 두 벌이 되어 한쪽만 고치는 실수가 나기 쉽다.

## 이름을 "전액취소"라 하지 않는다

이미 일부를 취소한 주문에서는 전액이 아니라 **남은 만큼만** 취소되기 때문이다. 사과 4개 중 1개를 이미 취소한 뒤 이 요청을 보내면 3개가 취소되고 환불도 3개분만 나간다. "전액"이라는 이름은 이미 취소된 몫까지 다시 환불하는 것으로 오해를 부른다.

## 생략과 명시는 결과가 같지만 경합에서 다르다

```
목록 생략   서버가 주문을 잠근 뒤 그때의 잔여를 읽어 채운다  →  조건 없이 처리
수량 명시   그 사이 다른 취소로 잔여가 줄었으면 초과로 거절   →  낙관적 확인
```

결함이 아니라 "내가 본 상태가 아직 맞는지" 검증받는 것이다. 잠금 범위는 [[부분취소-동시성-주문행-단일잠금과-캐시겹-미도입]], 잔여 계산의 정본은 [[부분취소-잔액-정본-수량기준-상태무관-누적]].

## 트레이드오프

기존 전액취소 API의 의미가 이 경로로 흡수되면서, 클라이언트가 "전액"을 의도했더라도 이미 취소된 몫은 반영되지 않는다. 용어 축 자체는 [[부분취소-스코프-배송전-품목수량-기반-금액입력-기각]]에서 정한 "취소=행위 / 환불=돈 흐름"을 그대로 따른다.
