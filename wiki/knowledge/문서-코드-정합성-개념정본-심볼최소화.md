# 문서-코드 정합성 원칙 — 문서는 개념·정책·왜의 정본, 현재 코드 형상·심볼은 코드가 단일 출처

## 한 줄 정의

**이유·정책·"왜"는 문서가 정본, 현재 코드 형상·심볼 목록(메서드·클래스·예외 클래스명·에러코드 상수·필드명)은 코드가 단일 출처.** 둘이 중복되는 순간 문서가 코드보다 뒤처진다. 이 원칙은 두 세션(루트 문서 체계 정비 #216, 전략 문서 코드 식별자 decoupling #288)에서 같은 형태로 도출됐고, 여기서 병합해 플랫폼 무관 일반 지식으로 남긴다.

## 왜 심볼 나열은 stale해지나

문서가 코드 심볼을 전수 나열하면 리팩터 시 **반드시** stale해진다. 예외 클래스 하나를 삭제하면 그 이름이 박혀 있던 문서 문장들을 연쇄적으로 고쳐야 하고, 안 고치면 문서가 코드와 어긋난다. 그래서:

- 루트 문서(PRD·ADR·architecture)는 **개념·정책만** 담고 심볼 목록은 코드에 위임한다. `architecture`는 서비스·컴포넌트를 전수 나열하던 표를 버리고 "어떤 책임이 어떤 순서로, 어떤 트랜잭션 경계 안팎에서 협력하는가"의 개념도로 슬림화(132줄 걷어내고 41줄 추가), 본문에 "개별 서비스를 전수 나열하지 않는다 — 정확한 목록은 코드가 단일 출처"를 못박았다. `PRD`는 task 본문을 흡수하는 대신 기능 표 한 행마다 상세(api-spec·ADR)·관련 task로 링크만 거는 인덱스형으로 전환.
- 전략·설계 문서(예외 처리 전략 문서 등)도 개념·원리만 기술하고 도메인별 구체 식별자를 최소화한다. 남기는 것은 **안정적 뼈대·계약**: 공통 예외 상속 축·전역 예외 핸들러 같은 컴포넌트의 개념, 의미 분류 카테고리 값, HTTP 상태코드 — 리팩터돼도 안 바뀌는 개념이라 stale 대상이 아니다.

## 동기화 판단 → 대조 표로 강등 (CLAUDE.md · PR 템플릿)

코드를 고친 뒤 어떤 문서를 갱신할지 매번 사람이 머리로 "판단"하면 누락이 생긴다. 그래서 **변경 종류 → 대상 문서를 고정 표에 박고, 작업 종료 시 그 표와 "대조"만 하는 기계적 절차**로 강등했다. 변경 종류(API 계약 / DB 스키마 / 구조 / 설계 결정 / 내부 구현만) → 대응 문서(api-spec / db-schema / architecture / adr / 없음). 같은 표를 CLAUDE.md와 PR 템플릿 **두 곳**에 두어 작업 흐름 어디서든 걸리게 했다(설계 결정은 ADR에 append — 기존 수정 금지, 새 번호 + supersede 표시라는 규율 포함).

## 문서 종류별 코드 식별자 허용도·판별 신호

| 문서 종류 | 코드 식별자 | 이유 |
|---|---|---|
| 현재 상태 반영(전략·아키텍처·상태) | **최소화** | 코드가 바뀌면 따라 바뀌어야 하므로 |
| 시점 스냅샷(결정 기록·회고·step) | 박아도 정상 | "그때 그렇게 결정했다"는 불변 기록이라 stale 대상 아님 |

**판별 신호: "이 코드를 리팩터하면 이 문서 문장이 틀려지는가?"** 그렇다면 그 이름은 개념으로 풀거나 "코드가 단일 출처"로 위임한다. 걷어내야 할 대상은 현재 상태를 계속 반영해야 하는 문서뿐이다.

이 정본/companion 경계는 commerce-brain wiki 자체의 운영 철학과 동형이다 — wiki는 "왜·트레이드오프"의 정본(모드 B)이고, 코드에 사는 계약·현재 동작은 코드가 정본이라 companion(모드 A)으로 인용만 한다. 이 원칙이 실제로 적용된 결정들이 이 wiki 곳곳에 있다.

## 소문자 파일명 통일·불변 원칙 1회 예외·grep 전수 검증

부수로 처리된 것들:
- **파일명 소문자 통일**(`PRD.md`→`prd.md`, `ADR.md`→`adr.md` 등). 단 codex 하네스(`.codex/`)는 전면 개편 이슈(#103)에서 곧 뒤집힐 것이라 이번 치환에서 의도적 제외.
- **macOS 대소문자 함정.** macOS 기본 FS는 대소문자 무구분이라 `docs/ADR.md` 링크가 실제 `docs/adr.md`를 로컬에선 멀쩡히 열지만 GitHub(Linux)에선 깨진다. 그래서 잔재를 "로컬에서 열어본다"가 아니라 **grep 전수 검색**으로 검증 — 이게 소문자화 치환 검증의 핵심 기법.
- **완료 task 문서 불변 원칙 1회 예외.** `ADR.md`→`adr.md` 개명으로 완료 task 문서의 `docs/ADR.md` 참조가 전부 깨진다. 방치(broken link)보다 예외적 일괄 수정(31개 task 파일 200곳+)의 비용이 낮다고 봐 원칙을 한 번 깼고, 그 사실을 별도 커밋으로 분리해 git 기록에 가시화했다. 원칙 자체는 [[backend-완료된-task-문서-불변-원칙]] 참조.

- 전략 문서의 나머지 섹션들(동시성 낙관 락, 외부 결제 결과 불명 처리, 유니크 제약명 식별 등)에도 구체 클래스·메서드명이 예전부터 다수 박혀 있다. 우선 인프라 캐시 장애 섹션만 정리했고 문서 전반 정리는 별도 이슈로 분리했다.
