## 배운 것
- **테스트가 내 가정을 뒤집었다**: "이 폴백은 런타임에 안 탈 거니 지우자"고 코드만 보고 판단해 제거했더니 통합테스트가 깨졌다. 알고 보니 그 폴백이 실제 주 경로였고, 정확하다고 믿은 1차 경로가 오히려 dead였다. 교훈: 죽은 코드처럼 보여도 제거 전에 테스트로 실제 런타임 경로를 확인. 예외 변환처럼 프레임워크 내부 동작은 코드 추론이 빗나가기 쉽다.
- **독립 리뷰의 수렴**: 로컬 multi-agent 리뷰와 Gemini가 같은 버그(제약명 판별 함수의 short-circuit 로직 결함, 상세는 파일 1)를 독립적으로 짚었다. 서로 모른 채 같은 결론이면 강한 신호.
- **버그 수정도 한 번에 안 됨**: 수정이 한 번에 수렴하지 않고 3회 반복됐다. 사용자가 "그러면 또 false 되는 거 아니냐"고 같은 함정을 다시 짚어준 게 전환점 — 내가 만든 수정이 같은 함정에 또 빠지는 걸 사람이 잡아줬다(수정 변천 상세는 파일 1).
- **발견한 근본 문제를 현재 작업에 끼우지 않기**: 작업 중 더 깔끔한 근본 개선(전역 예외 변환 빈 제거)을 발견했지만 현재 이슈 범위 밖. 판단 프레임 = "그거 안 고치면 현재 작업이 틀리거나 못 끝나나?" → 아니오면 현 제약에서 마무리하고 발견은 근거와 함께 별도 이슈로(#227) → 예면 현재 작업을 멈추고 선행을 먼저 별도 PR로 머지한 뒤 그 위에서 재개(선행 PR 위에 후속 PR을 쌓는 stacked PR 방식). 이번 건은 "전역 빈을 안 빼도 이중결제 매핑은 메시지 매칭으로 정상 동작" = 현재 작업이 틀리지 않으므로 별도 이슈(#227)로. 핵심은 "한 PR = 한 목적".
