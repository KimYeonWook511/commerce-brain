# 루트 문서 체계 정비 — 역할 경계 재정의·동기화를 대조로·파일명 소문자 통일

리팩터가 반복되면서 루트 `docs/` 문서들이 코드와 어긋나 stale해지는 문제를 잡은 세션이다(이슈 #214 해결). 원인을 "문서가 코드 심볼을 전수 나열하고, 변경 후 어떤 문서를 갱신할지 매번 사람이 판단한다"로 보고, ① 각 루트 문서의 역할 경계를 다시 긋고, ② 코드 변경 → 문서 갱신을 "판단"이 아니라 종류별 "대조"로 바꾸고, ③ 파일명 대소문자 컨벤션을 소문자로 통일했다. 같은 세션에서 harness 실행 단계 개편도 함께 진행했는데, 그중 task별 adr 템플릿의 staging 결정 방식 개편이 이번 루트 ADR 정비와 짝을 이뤘다.

## 결정한 것

### 1. 루트 문서 역할 분리 — 루트는 "현재 상태의 개념", 코드가 단일 출처

루트 문서는 현재 상태의 개념만 담고, 메서드·클래스명 같은 코드 심볼을 전수 나열하지 않는다. 심볼을 나열하면 리팩터할 때 문서가 반드시 stale해지기 때문이다. 세 문서의 역할을 이렇게 다시 그었다.

- **PRD** = 제품이 제공하는 기능의 상위 인덱스. 각 기능의 상세는 흡수하지 않고 api-spec·ADR·task별 문서로 링크만 건다. 실제로 새 PRD는 기능 표 한 행마다 "설명 / 상세(api-spec·ADR) / 관련 task"를 가리키고 "이 문서는 task PRD 본문을 흡수하지 않는다"를 명시하는 형태로 다시 썼다(기존 19줄 → 38줄, 흡수형이 아니라 인덱스형으로 전환).
- **ADR** = 프로젝트의 유일한 결정 타임라인. 설계 결정·정책·트레이드오프의 단일 출처. task 폴더 안의 adr는 그 task 진행 중의 staging 결정이고, 머지되면 최종 결정만 루트 ADR로 승격되는 관계(이 갈래가 같은 세션의 task adr 템플릿 staging 개편과 짝).
- **architecture** = 서비스·컴포넌트를 전수 나열하던 표를 버리고, "어떤 책임이 어떤 순서로, 어떤 트랜잭션 경계 안팎에서 협력하는가"를 보여주는 개념도로 슬림화. 실제로 architecture.md에서 132줄을 걷어내고 41줄을 더했으며, 본문에 "개별 서비스를 전수 나열하지 않는다 — 정확한 목록은 코드가 단일 출처"를 못박았다.

이 재정의의 뿌리 원칙: **이유·정책은 문서가 정본, 현재 코드 형상·심볼 목록은 코드가 정본.** 둘이 중복되는 순간 문서가 뒤처진다.

### 2. 코드 변경 후 문서 동기화를 "판단"이 아니라 "대조"로

코드를 고친 뒤 어떤 루트 문서를 갱신할지 그때그때 머리로 판단하지 않는다. 변경 종류별로 갱신 대상 문서를 표에 박아두고 그 표와 대조만 한다. CLAUDE.md와 PR 템플릿에 같은 표를 둔다.

- **왜 판단이 아니라 대조인가:** "이번 변경이 문서 갱신 대상인가"를 매번 판단에 맡기면 누락이 생긴다. 종류(API 계약 / DB 스키마 / 구조 / 설계 결정 / 내부 구현만)와 대응 문서(api-spec / db-schema / architecture / adr / 없음)를 고정 표로 만들면, 코드 작업을 마칠 때 표를 훑는 기계적 절차가 된다.
- **CLAUDE.md 재구성:** 핵심 규칙(언어·승인 게이트·불명확하면 멈춤·완료 task 불변·컨벤션 준수)을 최상단으로 올리고, "시점별 규칙(트리거 → 행동)" 표 두 개를 도입했다. (1) *명령 실행 전 컨벤션 확인* — `git commit` 전 commit-conventions, `gh pr create` 전 pr-conventions 식으로 어떤 문서를 언제 읽을지. (2) *코드 변경 후 루트 문서 동기화* — 위 변경종류 대조 표. 설계 결정은 결정 타임라인 문서(ADR)에 **append**(기존 ADR 수정 금지, 새 번호 추가 + supersede 표시)라는 규율도 함께.
- **PR 템플릿도 같은 대조 방식으로:** 기존 "문서/하네스 변경" 체크리스트("루트 기준 문서를 함께 수정했습니다" 같은 자기신고형)를 CLAUDE.md와 동일한 변경종류→대상문서 대조 주석 + "adr.md에 새 결정을 append 했습니다" 체크로 교체.

### 3. 파일명 소문자 통일 — 단, codex 하네스는 의도적 제외

루트 문서 파일명을 소문자 컨벤션으로 통일했다: `docs/PRD.md`→`prd.md`, `docs/ADR.md`→`adr.md`, `.github/ISSUE_TEMPLATE.md`→`issue_template.md`. 참조하는 모든 곳을 함께 갱신.

- **codex 제외 이유:** codex 하네스(`.codex/`)도 이 문서들을 참조하지만, codex 하네스 전체 개편이 별도 이슈(#103)로 이미 예정돼 있어 이번에 손대면 곧 다시 뒤집힌다. 그래서 `.codex/` 안쪽은 의도적으로 이번 치환에서 뺐다. 대신 루트 codex 진입점 가이드(AGENTS.md)는 `.codex/` **바깥**이라 이번 갱신에 포함해 참조를 소문자로 고쳤다.

### 4. 참조가 끊긴 harness 문서 삭제

CLAUDE.md 최상단의 자동 import(`@docs/claude-harness.md`)와 참고문서 링크를 둘 다 제거하자 `docs/claude-harness.md`를 가리키는 참조가 하나도 남지 않아 orphan이 됐다. 남겨두면 stale 문서가 유령으로 쌓이므로 파일째 삭제(50줄).

### 5. 완료 task 문서 불변 원칙을 이번 한 번 예외로 깬다

머지된 task 폴더 문서는 불변이 원칙이다. 그런데 루트 파일명을 `ADR.md`→`adr.md`로 바꾸면 완료 task 문서 안의 `docs/ADR.md` 참조가 전부 깨진 링크가 된다. 갈림길:

- **(A) 불변 고수 → broken link 수용.** 원칙은 지키지만 수백 개 죽은 링크를 방치.
- **(B) 예외적으로 완료 task 문서까지 일괄 수정.** 원칙을 한 번 깨는 대신 링크 정합성 회복.

**(B)를 택했다.** 죽은 링크를 방치하는 비용이 원칙을 한 번 깨는 비용보다 크다고 봤다. 완료 task 폴더 곳곳의 `docs/ADR.md` 참조를 일괄 치환했다 — 실제 규모는 31개 task 파일에 걸쳐 200곳이 넘는 참조였다(작업 전에는 대략 100여 곳으로 어림했으나 실측은 그보다 많았다). 원칙을 깬 사실은 별도 커밋으로 분리해 "왜 불변 문서를 건드렸나"를 git 기록으로 남겼다.

## 막힌 점·트레이드오프

### macOS ↔ GitHub 대소문자 함정 — 로컬 눈으로는 안 보이는 broken link

macOS 기본 파일시스템은 대소문자를 구분하지 않아서, `docs/ADR.md`를 가리키는 링크가 실제 파일 `docs/adr.md`를 가리켜도 로컬에선 멀쩡히 열린다. 하지만 GitHub(Linux, 대소문자 구분)에선 깨진다. 즉 로컬 확인만으론 잔재가 안 보이고 GitHub 웹에서만 드러난다. 그래서 소문자화 잔재를 "로컬에서 열어본다"가 아니라 **grep 전수 검색**으로 검증했다. 이게 이번 치환 검증의 핵심 기법이다.

### 원칙을 한 번 깬 대가

완료 task 불변 원칙을 예외로 깬 것 자체가 비용이다. 파일명 정합성을 우선했고, 그 예외를 눈에 띄게 만들기 위해 별도 커밋으로 분리해 의사결정 흔적을 남겼다(위 결정 5).

## 배운 것

- **문서가 코드 심볼을 나열하면 반드시 stale해진다.** 루트 문서는 개념·정책·"왜"만 담고 현재 형상·심볼 목록은 코드를 단일 출처로 두는 게 유지비가 싸다. 심볼을 부득이 박을 땐 "리팩터 시 함께 갱신해야 함"을 인지 대상으로 명시.
- **동기화를 사람 판단에 맡기면 누락된다 → 변경종류별 대응문서를 고정 표로 박고 대조로 바꾼다.** 판단을 기계적 체크로 강등하는 게 누락을 막는다. 같은 표를 CLAUDE.md·PR 템플릿 두 곳에 두어 작업 흐름 어디서든 걸리게 했다.
- **대소문자 파일명 변경의 잔재는 로컬(대소문자 무구분 FS)에선 안 보인다 — grep 전수로 검증해야 한다.** 로컬에서 링크가 열린다는 것이 GitHub에서 열린다는 보장이 아니다.
- **불변 원칙을 깨야 할 땐 방치 비용과 저울질하고, 깬 흔적을 별도 커밋으로 남긴다.** 원칙을 조용히 어기지 않고 예외임을 기록으로 가시화.

## 미해결·열린 질문

- **codex 하네스(`.codex/`)의 소문자 참조 정합성은 이번에 의도적으로 미뤘다.** 그 안쪽 문서들은 아직 `docs/ADR.md`(대문자) 등을 가리킬 수 있고, codex 전면 개편 이슈(#103)에서 한꺼번에 정리될 예정이다. 그때까지는 codex 경로에 임시 불일치가 남는다.
- 이번 세션은 PR 머지 전 스냅샷 기준으로 작성됐다(작성 시점엔 미머지 상태였고 이후 머지됨).
